# mcp-abap-adt-b 写入工具实操规则（经实测）

本 skill 编码了用 mcp-abap-adt-b 的写入工具（`CreateObject` / `UpdateObjectSource` / `ActivateObject`）在 SAP S/4 HANA 系统中创建/修改 ABAP 对象的实操规则与坑。经 MCP 实测验证，务必遵守。

## 什么时候用这个 skill

- 要在 SAP S/4 HANA 系统中创建 ABAP 对象（class / interface / program / include）
- 要修改已存在对象的源码
- 要激活 inactive 对象
- 遇到 Transport / corrNr / package 相关报错
- 需要给新建/修改的对象加修改日志注释

> 🔴 **授权前置**：本 skill 涉及的所有写入操作（CreateObject/UpdateObjectSource/ActivateObject）须先经用户授权。主 Claude 任务分配时会明示「已授权可执行」或「未授权只分析」。未授权绝不擅自执行。详见 abaper agent md 的授权强制规范。

## 支持的对象类型

- `CLAS/OC`（类）
- `INTF/OI`（接口）
- `PROG/P`（程序/报表）
- `PROG/I`（include）

**Function Module、DDIC 表/结构无法创建或改定义**——ADT 契约不同，本 MCP 不支持。

## 创建流程（CreateObject）

内部三步：POST → GET ETag → PUT。创建后对象为 **inactive**，必须再调 `ActivateObject` 才生效。激活后用对应 Get 工具读回验证。

## Transport 规则（最关键的坑）

- **$TMP 对象**（不传 `package`）：不传 `transport_request`，创建为 local object。
- **真实 package**（非 `$TMP`）：**必须传 `transport_request`**，否则报 `Parameter corrNr could not be found`。
- `transport_request` 传 **request 号**（如 `XL7K902092`），对象落到该 request 的**子 task**（如 `XL7K902093`）——这是 SAP 标准行为，不是 corrNr 失效。request 自身 E071 为空，对象在 task 的 E071 里。
- `UpdateObjectSource` 改真实 package 的对象时**同样必须传 `transport_request`**，否则 PUT 被拒。

## 多系统选择（system 参数）

写入工具（`CreateObject`/`UpdateObjectSource`/`ActivateObject`）同样支持可选 `system` 参数指定目标 SAP 系统 id；不传则用默认系统。多系统配置与默认系统选择见 `sap-basic-data-query` skill。单系统场景无需关心。**注意**：一次创建/更新/激活的完整流程（POST->GET ETag->PUT->Activate）须在**同一个 system** 上进行，不要中途换系统--系统在工具调用层已按 `system` 参数隔离 CSRF token/cookie，传同一个 id 即可保证一致。

## 源码要求

- 类的 source 必须是 DEFINITION + IMPLEMENTATION 整体；改类不能只传某一段。
- program/include 是单段源码体。
- **PROG/P 程序源码必须含 `REPORT <name>.` 声明**（`<name>` 为程序名，如 `REPORT zktest067.`）。该语句可在 Change Log 注释块之后，但必须在可执行 ABAP 语句之前。缺它则激活报 `The REPORT/PROGRAM statement is missing, or the program type is INCLUDE.`（EU 202）——仅注释 + `WRITE` 无法通过校验。include（PROG/I）不要加 `REPORT`。

## 修改日志注释模板（每次创建/修改必加）

凡经 `CreateObject` 创建或 `UpdateObjectSource` 修改的任何 ABAP 对象源码，**在整个 object 源码的最开头**必须加入一段修改日志注释块（英文）。注释须写明：代码由 Claude Code 生成、采用的 model、时间日期、agent 名字。即使是只改一行的小修改也要加。对已有源码做修改时，把该注释块加到现有源码最顶端（**不删除原有注释**，插在它们之前）。

注释模板（用 `"` 行内注释，避免与程序原有 `*` 块注释混淆）：

```abap
"*---------------------------------------------------------------------*
"* Change Log
"*---------------------------------------------------------------------*
"* Generated by : Claude Code
"* Model        : <model name, e.g. GLM-5.2>
"* Agent        : abaper
"* Date / Time  : YYYY-MM-DD HH:MM
"* Action       : Created / Modified
"* Object       : <object name>
"*---------------------------------------------------------------------*
```

说明：agent 运行时受环境限制，可能无法获取精确的当前时间。应使用所能得到的日期信息如实填写；若确实无法确定时间，写明日期即可，**不要编造精确到秒的时间**。

## MCP 源码位置

MCP server 的安装路径因环境而异，不要在文档里写死绝对路径。需要定位 MCP 源码或确认实际启用的 server 时，读项目的 `.mcp.json`（其中 `mcpServers` 的每个条目 `args` 指向该 server 的 `dist/index.js`）。改 MCP 源码后须 `npm run build` 并重启 MCP 才生效。ADT 底层契约（body XML 结构、ETag 流程、corrNr 规则）的完整记录见项目记忆 `adt-rest-create-update-contract.md`。
